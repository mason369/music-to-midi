## 根因与修复

- **WinError 5**：JSON 读写已有互斥，但服务存在性检查和清单路径构造绕过了互斥。CPython 3.11 Windows 的 `stat` / 最终路径解析可短暂持有不允许删除共享的句柄，阻止另一线程原子替换清单。现在构造器只解析稳定父目录，存在性检查进入同一个 `state_access`。原子写入不变，没有重试、sleep、吞异常或备用清单。两项回归使用实际 Win32 句柄及事件屏障，在旧代码确定性复现、修复后通过。依据：[CPython 源码](https://github.com/python/cpython/blob/v3.11.15/Modules/posixmodule.c)、[Windows 文件移动语义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)。
- **多轨起点**：Type 0/1 conductor 偏移由所有同步轨共用，Type 2 各序列独立。重复首拍、BPM／倍频纠错和裁切保持同一参考。六组真实多轨回归修改前失败、修改后通过。
- **窄窗口布局**：英文结果控件使用 QFrame 实际 `contentsRect()`，避免把边框算作空间而裁切控件。
- **解码／设备验收**：FFmpeg 对尾部标签严格拒绝或完整无损读取均核验真实结果；成功逐样本检查 PCM，失败检查原错误，生产坏帧、帧数和可用 MD5 校验不放宽。音量测试观察实际缓冲区消费，不假设固定 80 ms 回调，产品播放流程不变。
- **项目语言切换**：默认名称、项目状态、选择项及可访问标签同步切换；自定义名称和当前项目保留。项目结果重绘不会显示独立任务专用的删除按钮。复用两种语言既有翻译，不增加网络刷新。
- **Web 音色试听**：真实 Linux 包浏览器发现脚本从后端另一端口加载，与 `script-src 'self'` 冲突。脚本和样式改由页面同源提供，前端服务、API 网关及 Gradio 共用一个定义，不放宽 CSP，不使用 eval 绕过拦截。

### 乐谱与和弦追加验收

本轮对指定整曲追加了真实乐谱、ChordMini CUDA 和监听验证，并修复排谱中独立于模型推理的缺陷：

- 关闭 MuseScore MIDI 导入的二次演奏节奏重建。原实现使 1,029 个音符起点偏移，最大一拍；最终默认 1/32 乐谱的全部 **7,286 个音高／起点／结束时间与私有量化副本一致**，六声部、127 小节，源 MIDI 哈希未改变。
- 关闭时值简化后，MuseScore 官方 MIDI 导入器仍会截断同音高重叠。共享 `sheet_note_durations.py` 逐音匹配并恢复整曲 31 处结束时间：中音声部 2 处、贝斯 3 处、钢琴 26 处。跨小节用延音线衔接，已有声部容量不足时增加谱表；整曲钢琴的一处重叠需要第三谱表。不改源 MIDI，不增加模型推理或排谱转换次数。依据：[官方重叠处理](https://github.com/musescore/MuseScore/blob/v4.7.5/src/importexport/midi/internal/midiimport/importmidi_chord.cpp)。
- 三连音通过临时坐标变换和明确的 MusicXML 3:2 分组保留原时值，跨拍号、小节和复调延音线仍完整；不规则短小节尾部拆成合法二进制分组，修复 7/16 等拍号的分组错误。拍号按原音乐时间恢复，避免重复声明及等长的 3/4↔6/8 被 MuseScore 合并后产生数量不匹配。
