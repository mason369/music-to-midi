## 音乐转 MIDI v1.9.0

本次更新包含**桌面和弦随播、导出异常处理、Aria 官方流程对齐，以及 MuScriptor 乐器条件与时间轴日志修正**。模型权重、官方解码精度与七种处理模式保持不变。

### 和弦随播与导出

- 桌面结果页新增“和弦随曲播放”和独立 0～200% 音量。首次默认关闭随播、音量 100%，记忆后续选择；关闭随播仍可点击和弦试听，0% 静音两种试听。
- 和弦使用 ChordMini BTC 的原始识别区间，接入原音/MIDI 共用的音频时钟，跟随暂停、跳转、工程 BPM 和试听倍速。长和弦不会因小节显示切分重复发声；响度校准、音量和峰值保护仅影响试听，不写入 MIDI。
- 切换音色、关闭结果页或取消请求时阻止过期合成结果接入。中英文、窄窗口和键盘操作同步适配。此功能属于桌面 App，Space / Colab、独立 Web/API 与 Docker 不新增桌面和弦开关。
- 修复桌面下载 MIDI 或立体声 WAV 时，导出异常逃逸 Qt 回调导致闪退的问题。失败保留结果、显示真实错误并写入日志，允许修正后重试；取消保存和成功导出的内容保持原样。此项不代表 Issue #13 的所有长音频生成问题均已解决。

### Aria 与钢琴节拍

- Aria 长短音频预处理对齐官方分支；长音频使用已有 FFmpeg 按原声道重采样后再合并，首窗准备与模型加载并行。
- 补齐官方跨窗口恢复：非法序列交由下一个既有重叠窗口重新生成，不额外重跑旧窗口。未恢复的区间会报告具体秒数并停止输出，不把缺段 MIDI 当成完整结果。
- MIDI writer 使用固定官方 ariautils 提交 `7c815755c6889a784b6a1b3343e9e8daa3e7d128`，采用上游对同起点、零时值音符的修正；安装与便携运行同时校验依赖来源。没有加入自定义 token 约束、音符补丁或精度降级。
- 稀疏钢琴 BPM 汇总多个短乐句中的真实拍间隔，避免有足够证据仍被当成“长时间无节拍”；长空白不构造虚假拍点，固定速度可信度与变速证据继续保留。

### MuScriptor

- 桌面、Space、Colab 和独立 Web 导入音频、新增分轨时默认留空乐器条件，不再根据文件名自动施加条件；明确选择和已保存选择继续生效。
- 中英文说明明确：全选 35 类不是自动识别。手动选择既提供模型条件，也限制其他乐器输出。
- 时间轴日志报告官方 writer 实际采用的 onset 校正、小节偏移和净偏移；完成写出前显示待计算，复用实例清空旧值，写出失败不发送完成信息。与未增加观测的官方 writer 对照，MIDI 字节相同。

### 实测与已知限制

- 本机全仓后台回归 **1,783 通过、3 项真实音频设备检查跳过**；中英文共享目录各 636 键，独立 Web 各 271 键，完成键与占位符一致性检查。桌面、Space/Colab、Web/API、Docker、便携/可执行与发布契约均纳入检查。源码验收不等于所有硬件或云端 GPU 都已实测。
- RTX 4070 Ti SUPER 上，240.9836 秒完整流行歌曲使用 MuScriptor Large 官方自动识别，输出 **8 轨、6,560 个有效音符**，无 token 上限警告或闪退，含加载与节拍分析总耗时约 337.4 秒。音符数量不是识别准确率评分。
- **35 类条件生成问题仍保留**：不同歌曲的 5 秒片段也可触发 2,000 token 上限，或未触及上限却没有可用音符。上限按每个 5 秒窗口计算，不是整曲时长限制；五分钟不是安全阈值，也不宣称所有歌曲必现。
- **Aria 官方仍可能生成非法序列**：独立 Torch/torchaudio 2.5.0 对照也复现，随后由官方下一窗口恢复。应用当前环境的 240.9836 秒钢琴样本输出 6,598 条有效音符；没有保证所有输入都能恢复。
- 两项既有依赖声明冲突暂保留：Aria 的 torchaudio 上界与桌面固定 2.7 不一致，audio-separator 的 NumPy 下界与桌面固定 1.26 不一致。没有为消除提示改写官方包元数据或替换已验收运行时。

详细证据见 [MuScriptor 分析](https://github.com/mason369/music-to-midi/blob/v1.9.0/docs/muscriptor-model.md)与[钢琴转写分析](https://github.com/mason369/music-to-midi/blob/v1.9.0/docs/piano-transcription.md)。

## Music to MIDI v1.9.0

This release adds **desktop chord accompaniment, export error handling, official Aria pipeline alignment, and MuScriptor conditioning and timing-log fixes**. Model weights, official decoding precision and the seven processing modes remain unchanged.

### Chord playback and export

- Desktop results gain **Chords follow song** and independent 0–200% volume, initially off/100% with persistent preferences. Disabling follow preserves click auditions; 0% mutes both.
- ChordMini BTC's native intervals share the original/MIDI audio clock for pause, seek, project BPM and preview speed. Visual bar divisions do not retrigger long chords. Loudness calibration, volume and peak protection affect monitoring only, never MIDI.
- Stale synthesis is rejected after cancellation, SoundFont changes or closing results. Both languages, narrow windows and keyboard controls are supported. This is a desktop App feature; Space / Colab, standalone Web/API and Docker do not gain desktop chord controls.
- MIDI and stereo-WAV export errors no longer escape Qt callbacks and terminate the desktop application. Errors retain results for correction and retry, display their cause and preserve logs; cancellation and successful exports retain their content. This does not claim to resolve every long-audio generation report in Issue #13.

### Aria and piano tempo

- Aria preprocessing follows the official short/long branches. Long audio uses the existing FFmpeg executable to resample original channels before averaging; first-window preparation overlaps model loading.
- Official overlapping-window recovery is implemented without extra retries of previous windows. Unrecovered intervals report timestamps and stop output instead of publishing incomplete MIDI.
- The MIDI writer is pinned to official ariautils `7c815755c6889a784b6a1b3343e9e8daa3e7d128`, adopting upstream same-start and zero-duration note fixes. Installation and portable runtime validate source identity. No custom token constraints, note patches or precision reduction were introduced.
- Sparse-piano BPM fitting pools real intervals across short phrases instead of discarding otherwise sufficient evidence. It invents no beats in long silences and retains fixed-tempo uncertainty and variable-tempo evidence.

### MuScriptor

- Audio imports and new stems default to empty instrument conditioning across desktop, Space, Colab and standalone Web. Filenames no longer impose conditions; explicit and saved selections remain effective.
- Both languages clarify that selecting all 35 classes is not automatic detection. A manual selection both conditions the model and excludes other instruments.
- Timing logs report the official writer's actual onset correction, bar offset and net shift. Values remain pending until writing finishes, reused instances reset them, and failed writing does not report completion. Output bytes match the official writer without observation.

### Verification and known limits

- Local background regression: **1,783 passed; 3 physical audio-device checks skipped**. Both languages passed key and placeholder parity with 636 shared keys and 271 standalone Web keys each. Desktop, Space/Colab, Web/API, Docker, portable/executable and release contracts were checked; source verification is not universal hardware or cloud-GPU acceptance.
- On an RTX 4070 Ti SUPER, a complete 240.9836-second pop recording produced **8 tracks and 6,560 valid notes** with MuScriptor Large automatic conditioning, without token-limit warnings or a crash. Total time including loading and beat analysis was about 337.4 seconds. Note counts are not accuracy scores.
- **The upstream all-35-condition issue remains.** Five-second excerpts can exhaust 2,000 tokens or produce no usable notes without exhausting the limit. The limit applies per five-second window, not per song. Five minutes is not a safe threshold, and universal failure is not claimed.
- **Official Aria decoding can still emit invalid sequences.** An independent Torch/torchaudio 2.5.0 run reproduced this and recovered through the next official window. The application's accepted 240.9836-second piano run produced 6,598 valid notes; recovery is not guaranteed for every input.
- Two existing dependency metadata conflicts remain: Aria's torchaudio upper bound versus desktop 2.7, and audio-separator's NumPy lower bound versus desktop 1.26. Upstream metadata and the accepted application runtime were not rewritten to suppress these reports.

Detailed evidence: [MuScriptor investigation](https://github.com/mason369/music-to-midi/blob/v1.9.0/docs/muscriptor-model.md) and [piano transcription investigation](https://github.com/mason369/music-to-midi/blob/v1.9.0/docs/piano-transcription.md).
